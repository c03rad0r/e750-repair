# E750 AP+STA and br-lan migration

This role converts the E750's LAN from plain `eth0` to a `br-lan` bridge and
enables a 2.4 GHz AP on the same radio as the existing STA uplink. It is the
base for standalone TollGate (portal on the AP, STA as WAN) and for the later
combined BSBF+TollGate mode.

## Topology

```text
2.4 GHz radio0 (channel 11)
├── phy1-sta0  mode sta  network wwan   -> hermes-lan (uplink, metric 9)
└── phy1-ap0   mode ap   network lan    -> br-lan
                                          └── eth0 (192.168.8.1/24, DHCP)
```

The AP and STA must share the channel; `e750_ap_channel` defaults to `11`, which
is the current STA channel. Airtime is shared, so portal clients get less than
the STA backhaul.

## Safety: watchdog rollback

The role:

1. backs up `/etc/config/{network,wireless,firewall}` to
   `/tmp/e750-ap-backup/`;
2. applies the bridge and AP;
3. **arms a watchdog before reloading** — if `/tmp/e750-ap-confirmed` is not
   created within `e750_ap_watchdog_seconds` (default 600), it restores the
   backup and reloads network/wireless/firewall;
4. reloads and prints the state, but does **not** confirm.

This is the safety net while the serial adapter is unreliable. If SSH drops,
wait for the watchdog and reconnect on the old `eth0` LAN.

## Apply and confirm

```bash
ssh x280
cd ~/e750-repair
LC_ALL=C.UTF-8 ansible-playbook -i inventory/e750-ssh.yml playbook-e750-ap.yml

# verify from x280 (and a WiFi client):
ssh -i ~/.ssh/id_ed25519 root@192.168.8.1 \
  'ip -br a show br-lan; iw dev; iw dev phy1-sta0 link; ps w | grep [h]ostapd'

# only after verification:
LC_ALL=C.UTF-8 ansible-playbook -i inventory/e750-ssh.yml playbook-e750-ap-confirm.yml
```

The AP is **open** by default (`e750_ap_encryption: none`) because a TollGate
captive portal handles authentication. For a WPA2 AP:

```bash
... playbook-e750-ap.yml -e e750_ap_encryption=psk2 -e e750_ap_key='...'
```

## Rollback

```bash
LC_ALL=C.UTF-8 ansible-playbook -i inventory/e750-ssh.yml playbook-e750-ap-rollback.yml
```

This restores the pre-change config and removes the confirm flag. The backup is
in `/tmp`, so a reboot clears it; take a config archive before a long-lived
change.

## Live result (2026-10-29)

Applied on the E750 and confirmed:

```text
br-lan   192.168.8.1/24, eth0 as bridge port
phy1-sta0  SSID hermes-lan, channel 11, connected (-22 dBm)
phy1-ap0   SSID TollGate-E750, channel 11, type AP, 20 dBm
hostapd    phy1-ap0: AP-ENABLED; AP-STA-CONNECTED 50:76:af:2f:33:ed
client     scan sees TollGate-E750; association succeeds; ping 2/2 to 192.168.8.1
```

Two fixes were required and are now in the role:

- **Unique AP MAC.** With both vifs on the same permanent MAC, hostapd logged
  `handle_probe_req: send failed` and the AP was not scannable. Setting
  `wireless.default_radio0.macaddr` (locally administered, default
  `02:83:c4:4d:fc:3b`) gives the STA the permanent MAC and the AP a distinct one.
- **Full `wifi down`/`wifi up`** after the bridge change. A plain `wifi reload`
  left the AP un-beaconed on ath9k; the role now creates `br-lan`, then restarts
  wireless cleanly, with `beacon_int=100`/`dtim_period=2`.

`handle_probe_req: send failed` can still appear in bursts (a known ath9k/AP+STA
symptom), but the AP beacons, a client associates and traffic flows. Watch it in
a soak; if clients fail to associate, capture `logread | grep hostapd`.

DHCP was not exercised by the static test IP; it is part of the TollGate
standalone test.

Evidence: `evidence/ap/2026-10-29_ap-sta.txt`.

## Verification checklist

- `br-lan` exists with `192.168.8.1/24` and contains `eth0` + the AP.
- `iw dev` shows `phy1-ap0` (AP) and `phy1-sta0` (STA); the STA is associated.
- `hostapd` is running; a client can associate with `TollGate-E750` and gets a
  DHCP lease.
- `ubus call network.interface.lan status` is up and `"device":"br-lan"`.
- Firewall reloaded: `nft list ruleset | grep 'iifname "br-lan"'` shows the LAN
  rules (fw4 resolves the zone to the new bridge).
- BSBF still healthy (`/usr/bin/e750-health`), endpoints intact, egress = server.

## Caveats

- The AP is on the same 2.4 GHz radio as the STA; throughput is shared.
- `eth0` becomes a bridge port, not a routed interface; the IP moves to
  `br-lan`.
- The firewall zone is reloaded so fw4 resolves `lan` to `br-lan`; without that,
  LAN clients fall into the WAN/INPUT policy.
- TollGate is **not** installed by this role; it is the next PR.
- Do not run the AP change without a tested rollback and the second gateway
  available.
